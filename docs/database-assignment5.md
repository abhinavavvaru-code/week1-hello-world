# Assignment 5 database contract

Apply `supabase/migrations/202610120001_assignment5.sql` after the Assignment 4 migration. It is transactional and additive: existing captions, ratings, prompts, identities, and the old RPC signatures remain. Existing generations receive `topic='campus'`, `perspective='observer'`, and `format_version=4`; their caption text is unchanged. Newly reserved generations use format 5.

The `caption-uploads` bucket is private, accepts JPEG only, and limits files to 1 MiB. Upload to the exact path `<user UUID>/<image UUID>.jpg`, with no overwrite/upsert. A member can insert only into their own folder. A transaction advisory lock prevents simultaneous inserts from exceeding 20 retained uploads created on the current New York calendar day. Successful registration separately permits 20 image metadata rows per member per day. Cleanup of an unregistered orphan releases its Storage slot; registered metadata remains immutable. These database limits complement the API's JPEG validation, size checks, and generation limit.

Before publication, only the owner can read the file or its image metadata. Once a succeeded generation has a caption using the file, signed-in members can read it. Anonymous requests remain denied. A file can be deleted only by its owner while it has no registered image metadata. Cleanup takes the same lock as registration, preventing cleanup from deleting a file after an ambiguous or concurrently committed registration response. Registered files cannot be deleted or updated, preserving published captions and exports. The existing avatar bucket and its policies are preserved.

No generation prompt is published. Uploaded metadata should use a generic description for `p_alt`; the user's scene and context belong in the owner-only generation prompt. The new feed returns author UUIDs and a first-name/last-initial display label. Missing or email-like first names become `Member`. It never reads an email address from `auth.users`, and it does not loosen the profiles table's owner-only RLS.

The privileged implementations and policy helpers remain in `punchline_private`, with empty search paths and fully qualified relations. The five new exposed RPCs are authenticated-only invoker wrappers. Do not expose `punchline_private` through the Data API. The old private completion implementation is renamed and its member execute privilege revoked; the old completion RPC dispatches format-5 records through the stricter rules, closing a legacy-call bypass.

## New RPCs

`register_caption_image_v5(p_image_id uuid, p_title text, p_alt text)` returns scalar text `upload-<image UUID>`. It verifies the exact file exists in the caller's folder, stores `src=''`, `scene=p_alt`, `owner_id`, and `storage_path`, and enforces 20 registrations per New York day. Title length is 1–100 trimmed characters; alt length is 1–300. Retrying the same ID and same metadata returns the existing ID, even at the quota. Reusing the ID with different metadata fails.

`reserve_caption_generation_v5(p_request_id uuid, p_image_id text, p_prompt text, p_style text, p_system_prompt text, p_model text, p_topic text default 'campus', p_perspective text default 'observer')` returns an array with one reservation: `id`, `user_id`, `image_id`, `prompt`, `system_prompt`, `style`, `provider`, `model`, `request_id`, `status`, `created_at`, `completed_at`, `topic`, `perspective`, and `is_new`. Only a new reservation should trigger an AI call. It retains the atomic five-attempt daily limit, input validation, idempotence, and two-minute stale-pending expiry from Assignment 4. Uploaded images must belong to the caller, even if somebody else's photo is already published. The old reserve RPC delegates here with the default options.

Styles: `dry`, `chaotic`, `wholesome`, `wordplay`, `roast`. Topics: `campus`, `study`, `roommates`, `nyc`, `food`, `internet`, `other`. Perspectives: `observer`, `student`, `roommate`, `tourist`, `object`. Explicit null or invalid values fail; omitted optional fields use the defaults.

`complete_caption_generation_v5(p_generation_id uuid, p_captions text[])` returns the three stored caption rows: `id`, `generation_id`, `content`, `position`, `created_at`. It atomically publishes exactly three captions, distinct ignoring case, each 5–140 characters and at most 12 words. The SQL trim and word counter match JavaScript whitespace, including nonbreaking spaces. Failed validation saves no partial captions. Completed-generation retries return the saved results unchanged, including historical captions that exceed the newer limits.

`get_caption_feed_v5()` returns the original fields `id`, `content`, `image_id`, `created_at`, `style`, `laughs`, `groans`, `my_vote`, `voted_at`, plus `author_id`, `author_name`, `image_src`, `image_alt`, `storage_path`, `topic`, `perspective`, `week_upvotes`, and `month_upvotes`. All-time counts include every rating. Period counts include only upvotes cast inside the current New York calendar week (Monday start) or month, using both start and end boundaries; caption creation date does not determine a vote's period. The image source is a local SVG for presets and empty for uploaded photos. Render uploaded photos through the authenticated application image endpoint rather than an unsigned public Storage URL.

`get_caption_image_v5(p_caption_id uuid)` returns a scalar Storage path only for a caption joined to a succeeded generation. Seed artwork or missing/unpublished captions return null. This is the narrow lookup for the authenticated `/api/captions/<caption UUID>/image` endpoint. Storage RLS independently enforces owner-or-publication access when the endpoint downloads the file.

The existing `fail_caption_generation` and `get_generation_allowance` remain unchanged. Ratings remain one insert per caption and member. Duplicate, spoofed, edited, and deleted ratings remain denied. Profiles and legacy votes retain their original restricted grants.

## Verification and limits

Run `supabase/verification_v5.sql` for read-only bucket, policy, function, version, and caption-integrity checks. `supabase/tests/assignment5_security.sql` tests two identities, upload ownership, immutable metadata/files, cleanup, private-versus-published reads, legacy limits and dispatch, generation options, email-safe attribution, calendar scores, quotas, and anonymous denials. Its fixtures roll back. `concurrent_uploads_v5.py` exercises 32 simultaneous local Storage inserts and verifies exactly 20 succeed. The local Storage bootstrap models database rows and policies; it does not exercise Supabase's actual byte storage, MIME detection, or upload API. Verify a real JPEG upload and generation through the deployed app after migration.
